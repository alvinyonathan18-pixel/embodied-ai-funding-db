# Unitree funding history from its STAR Market prospectus

All figures (event amounts, yearly sums, check counts) are in
[docs/results.md](docs/results.md), which is generated by
`scripts/make_results.py`. This README contains no figures of its own.

## What this project is

A single-company case study: the funding history of Unitree (宇树科技),
built from its STAR Market (科创板) prospectus (招股说明书). Extracted
fields carry a verbatim evidence quote from the saved prospectus text.
amount_total_wan_cny, cash_flow_year, unit_basis and investor_count are
computed by scripts, not quoted. See Limitations for fields whose quote is
weak or inferred. Validity matters more than volume. The results describe Unitree only and do not
generalize to the embodied-AI sector.

## Question and scope

Question: which capital increases (增资) brought cash into Unitree in 2024
and 2025 (by registration year, or by paid-in year where a paid-in date is
stated, which brings in E01b), and does their yearly sum equal the
cash-flow line 吸收投资收到的现金 in the prospectus for those years?

2022 is out of reconciliation; 2023 has no events and is checked only as
nil = nil.

Events extracted:

| event_id | What it is |
|---|---|
| E05 | Investor capital increase registered in 2024 |
| E06 | Investor capital increase registered in 2024 |
| E07 | Investor capital increase registered in 2025 |
| E08 | Incentive-platform (上海宇翼) capital increase registered in 2025 |
| E01b | 上海宇翼 component of the capital increase registered in 2022, paid in 2025 |

The 2022 events E01, E02 and E04 are deliberately not extracted (narrowed
scope). Capital reserve conversions, secondary share transfers,
shareholding reform and the IPO are out of scope. Full definitions:
[docs/scope.md](docs/scope.md) and
[docs/data_dictionary.md](docs/data_dictionary.md).

## Method

Rule 2a in docs/data_dictionary.md; a row can be verified only after:

- (a) every evidence quote of the event is an exact substring of the saved
  prospectus text (`scripts/check_quotes.py`);
- (b) the sum of the event's investor amounts equals the 合计 stated in the
  prospectus (`scripts/check_sums.py`); events with no stated 合计 (E08,
  E01b) are NO_TOTAL and can only be checked through (c);
- (c) the yearly sum of events by cash-flow year (year of paid_in_date if
  present, otherwise of registration_date) equals 吸收投资收到的现金
  (`scripts/check_year_totals.py`). Arithmetic is decimal.Decimal only.

## How to run

Python 3, standard library only. Run from the repository root, in this
order:

```bash
python scripts/build_events.py
```

Rebuilds data/events.csv from data/extractions/, data/investor_rows.csv and
data/event_totals.csv; the status column is copied unchanged.

```bash
python scripts/check_sums.py
```

One line per event (OK, NO_TOTAL, MISMATCH or ERROR) and a summary line.
OK and NO_TOTAL are not failures.

```bash
python scripts/check_year_totals.py
```

One line per year (OK, MISMATCH or EXCLUDED), CROSS-CHECK lines, one line
per cash-flow quote (PASS, FAIL or SKIP), and a summary line.

```bash
python scripts/check_quotes.py data/extractions/E05.json raw/unitree/sse_prospectus_shenbaogao_20260320.txt
```

Repeat for E06, E07, E08 and E01b (all quote the same SSE file). One PASS,
FAIL or SKIP line per field and a summary line; any FAIL is a failure.

```bash
python scripts/make_results.py
```

Runs check_sums.py, check_year_totals.py and check_quotes.py (once per
event JSON; SKIP when the raw file is not on disk) and prints
`Wrote .../docs/results.md`. If its own yearly statuses disagree
with check_year_totals.py, or events.csv disagrees with
investor_rows.csv, it prints the disagreement and writes nothing.

```bash
python -m unittest discover -s scripts/tests -v
```

Runs the tests of make_results.py on synthetic data; every test should
end in `ok`. The other scripts have synthetic fixtures with expected
output in scripts/tests/synthetic_*_expected.txt.

On a fresh clone without raw/, the quote lines show SKIP instead of PASS
(and check_quotes.py stops with a file-not-found error); everything else
should match section (c) of docs/results.md.

## Limitations

- Reconciliation is against the same prospectus, not an independent source.
- Both source documents are pre-listing drafts (SSE 申报稿 and cninfo 上会稿), not the final registered prospectus.
- All event rows were extracted from the 申报稿 only; the 上会稿 is used only for the 2024 and 2025 cash-flow lines.
- 2024 and 2025 reconcile, and 2023 is nil = nil (trivial).
- The 2022 events (E01, E02, E04) are not extracted, so 2022 is excluded from reconciliation with an unexplained gap; the 2022 cash-flow line value is in [docs/results.md](docs/results.md), section (b).
- E08 and E01b have no stated total and are verified only in aggregate with E07 for 2025.
- Share transfers are excluded, so totals are money into the company, not cap-table movement.
- registration_date is shared by E06 and an equity transfer, and by E07 and E08.
- E01b was registered in 2022 but paid in 2025, and its cash_flow_year follows paid_in_date.
- share_count_wan (万股) and registered_capital_wan (万元注册资本) are different units, and the jump in amount per unit between E06 and E07 is unexplained.
- agreement_date is not uniform: E07 uses the shareholder-meeting date with the agreement inferred from 同日, E08 uses the approving meeting date, and E05, E06 and E01b use signing dates.
- event_type for E05, E06 and E07 is a manual classification whose evidence quote is only a section heading.
- The 51 investor rows of E05, E06 and E07 (investor_round; count in docs/results.md, section (a)) have no quote column, so no script checks investor names or amounts against the text.
- Their only script checks are the sum check against the stated total and the yearly cash-flow check, which cannot detect two investors whose amounts are swapped or a misspelled name.
- The manual check of these rows is recorded in data/verification_log.csv:
  - For each of E05, E06 and E07, a log row records that all investor rows were compared against the rendered page images of the SSE 申报稿 (names, the quantity column and 增资款), with the checker named.
  - Those log rows say a first-pass comparison was done by an AI assistant outside the repository and the checker then confirmed on the pages; that first pass is not reproducible from the repository.
  - The check is against the same document the rows were extracted from, and those log rows leave the correct column empty.
- 中网投资 (SSE) and 中网投 (cninfo) are not merged.
- The raw prospectus text files are not in the repository, so on a fresh clone check_year_totals.py reports its quote checks as SKIP and check_quotes.py stops with a file-not-found error.
  - Needed files, both in `raw/unitree/`: `sse_prospectus_shenbaogao_20260320.txt` (SSE 申报稿) and `cninfo_prospectus_shanghuigao_20260525.txt` (cninfo 上会稿), named exactly as in data/cashflow_lines.csv.
  - The user must obtain the PDFs from SSE and cninfo; the source URLs, access date and SHA-256 hashes are recorded in data/raw_sources.md.
  - `pdftotext -layout -enc UTF-8 <pdf> <txt>` with pdftotext 4.06 (xpdf) reproduces the saved .txt files byte for byte; compare the result with the hashes in data/raw_sources.md.
- Single company: the case was chosen because a prospectus exists, which is itself a selection effect (see docs/scope.md).
- The prospectus lists capital increases without round names, so no stage (A轮, B轮, ...) is reported.
